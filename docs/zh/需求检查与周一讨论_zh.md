## 3. 数据检查与预测目标

实测完整 CSV 为 **36,733 × 12**，所有列都是数值；`year` 为整数，其余为浮点。
缺失单元格为 0，非有限数为 0，完全重复记录 7 条。按年行数：2011=7,411；2012=7,628；
2013=7,152；2014=7,158；2015=7,384。全数据只做这些结构检查；分布及建模诊断只在开发期进行。

| 字段 | 含义 | 课程指南单位 | 本方案用途 |
|---|---|---|---|
| year | 2011–2015，同一年内按时间排序 | 年 | 划分、诊断，不作为输入 |
| at | 环境温度 | °C | 输入 |
| ap | 环境压力 | mbar | 输入 |
| ah | 环境相对湿度 | % | 输入 |
| afdp | 空气过滤器差压 | mbar | 输入 |
| gtep | 燃气轮机排气压力 | mbar | 输入 |
| tit | 涡轮入口温度 | °C | 输入 |
| tat | 涡轮后温度 | °C | 输入 |
| tey | 涡轮能量产出 | MWh | 可作为输入，禁止作为目标 |
| cdp | 压缩机出口压力 | mbar | 输入 |
| co | 一氧化碳浓度 | mg/m³ | 建议目标 |
| nox | 氮氧化物浓度 | mg/m³ | 可选目标；选 CO 时不作输入 |

单位忠实采用课程数据指南；需要物理换算时先核对数据源，不能按列数值直觉自行换单位。

仅 2011–2013 的检查发现：

- CO 最小值 0.00038751，中位数 1.5242，均值 2.21439，95% 分位数 6.1675，最大值 44.103 mg/m³。
  长尾明显，百分比误差会被接近零的分母放大；MAE 较直观，RMSE 暴露大误差。
- NOx 中位数 67.096，95% 分位数 87.1325，范围 27.765–119.91 mg/m³。
  如果小组更关注氮氧化物监测，可以改选 NOx，但必须重定误差阈值并重跑所有模型。
- 开发期有 380 行湿度 >100%，最高 100.2%；这可能涉及测量/取整，证据不足不删除、不强制截断。
- `gtep` 与 `cdp` 的 Pearson 相关约 0.994；`tey` 与 `cdp` 约 0.989。
  相关性提示共线性和重复信息；OLS 系数解释须谨慎，不能当因果关系。
- 无缺失，但仍将中位数填补放在 Pipeline 中，为未来缺失提供明确处理；不会先在全数据拟合填补器。
- 重复记录可能是连续稳定工况。保留原始顺序、不凭重复就删行；若以后核实是复制错误，再记录统一修正与重跑。
- 指南说明是小时平均，但 CSV 只有年份，没有完整时间戳；不能断言相邻行严格相差一小时。

**建议工程问题：** 使用当期环境与工况测量，在不依赖第二个污染物分析仪的情况下，
能否提供足够准确、计算代价合适的 CO 虚拟传感器，辅助操作员监测？
这是同一时刻浓度估计，不是未来一小时预测，也不是排放合规认证。

**建议理由：** CO 是允许的真实排放目标，长尾与近零值让比较更有分析价值；
CW1 已有相关理解可以用于学习，但本次要在统一协议下重新运行，不搬用其测试结论选模型。
排除 NOx 是为避免部署时仍依赖另一污染物测量；TEY 需确认在推断时确实可获得。

## 4. 部署约束草案：必须在看候选结果前确认

| 约束草案 | 理由 | 尚需确认 |
|---|---|---|
| 至少 90% 样本满足绝对 CO 误差 ≤1 mg/m³ | 逐条误差容限比平均误差更接近监测可用性；接近零的 CO 不适合普通 MAPE | 1 mg/m³ 与 90% 是用于讨论的工程假设，没有厂家/法规依据；需小组/使用方认可 |
| 所记录单线程 CPU 上，完整 Pipeline 单条预测中位数 ≤10 ms | 为服务接入留出计算预算；数据为小时平均，简单 CPU 部署有现实性 | 10 ms 是服务预算草案，数据没有给出实时 SLA；需确认硬件、统计量与预算 |

这两项约束都能实际测量，但数值不能被写成“行业规定”。精度阈值不是从测试数据选出。
如果小组没有合理的 10 ms 应用需求，可仅采用精度约束（brief 允许 1 项），
效率仍须实测比较。若决定监测高浓度风险，可在开发期预先定义额外尾部诊断；不要随意声称法定超标。

当前可行性筛选采用“平均验证覆盖率 ≥90% 且单条中位数 ≤10 ms”；另展示最差折覆盖率。
若希望每个时间段都达到覆盖要求，应在实验前把规则改为“每折都通过”，并让所有模型遵守同一规则。
所有模型都失败时，应说明当前没有可行方案，不能事后降低要求来宣布成功。

## 5. 统一实验设计与候选模型

### 划分、指标及泄漏控制

1. 开发集为 2011–2013（22,191 行），保留测试为 2014–2015（14,542 行）。
   沿用课程指南的作者划分，符合“用历史训练、部署到未来”的问题。
2. 开发集固定五折 `TimeSeriesSplit`，扩展训练窗口，验证严格在训练之后，禁止随机打乱。
   草案 `gap=24` 行；这只是减轻相邻测量依赖的假设，不等于确认了 24 小时，也不能保证独立。
   同一 `FOLDS` 列表供每个模型调用，并保存边界。待开发期比较 gap=0/24/168、整年留出稳健性。
3. 主调参指标统一 MAE；辅助 RMSE、R²、容限覆盖率、负预测比例。
   五折验证块等长，因此平均覆盖率也等于这些验证预测合并后的覆盖率；最早训练段不计入验证覆盖。
   报告每折值、均值及折间 SD，SD 不是独立样本标准误或置信区间。
4. 每折仅在训练部分拟合中位数填补和标准化。树模型无需标准化；这是合适的模型专属处理，
   但原始输入、划分、折与评分一致。禁止全数据标准化、全数据挑特征或用测试残差改参数。
5. 现有 `run_search` 用 `GridSearchCV(refit='mae', return_train_score=True, n_jobs=1)`；
   评分器内部将 MAE/RMSE 取负以便最大化，表格还原正误差。
6. 树模型固定种子 42；OLS 确定性计算，本身没有 `random_state`。
   改种子、目标、特征、gap 或阈值后，要统一重跑并更新协议记录。

**重要的历史暴露限制：** CW1 已经对同一个 2014–2015 测试集评估过多个线性模型。
CW2 当前没有测试预测，但这不使旧数据重新成为“从未见过”的盲测。
不使用 CW1 测试排名指导新方案；报告诚实披露先前暴露。
若课程要求严格意义的新独立盲测，需要教师认可的更新/外部数据；不能通过重新随机切分旧数据抹去暴露。

### 三个候选模型，加上 OLS

| 模型 | 提出它的原因与风险 | 草案调参网格 | 预处理 |
|---|---|---|---|
| LinearRegression | 简单、快、可解释；可能漏掉非线性，共线性影响系数 | 无常规待调超参数，单一配置以相同 5 折测量 | 中位数填补 + 标准化 |
| RandomForestRegressor | 多树平均学习非线性和交互；可能过拟合且外推差，模型较大 | `n_estimators=[100,300]`, `max_depth=[8,None]`, `min_samples_leaf=[2,10]`；`max_features=.8` 固定 | 中位数填补 |
| ExtraTreesRegressor | 额外随机切分提供另一种偏差/方差权衡；不预先宣称更快或更准 | 同随机森林的 8 组网格与固定 max_features，便于比较 | 中位数填补 |
| HistGradientBoostingRegressor | 顺序迭代补偿残差，可能适合表格非线性；学习率/复杂度需控制 | `learning_rate=[.05,.1]`, `max_leaf_nodes=[15,31]`, `l2_regularization=[0,1]`；`max_iter=200` 固定 | 中位数填补 |

每个候选 8 配置 ×5 折=40 次搜索拟合，再开发集重拟合 1 次。
HGB 使用 `early_stopping=False`，避免默认随机内部验证破坏时间协议。
相同候选数量不意味着相同计算预算，所以必须同时记录整个搜索成本与最终模型成本。
三个候选均属于不同 ensemble 估计器；brief 不要求分属三种完全不同大类，选择理由必须来自问题。
如组员对其中一种不熟悉，可在讨论时换成 SVR 或二次 Ridge，但要先定共同协议再比较。

### 调参与过拟合分析

- 参数网格在候选结果前记录；每个模型都调好以后再做最终比较。OLS 无可调正则化强度，说明原因即可。
- 当前按最低平均验证 MAE选择每个家族配置，再按部署约束筛选家族；不要用测试集筛选。
  若“以覆盖率优先调参”更贴近最终业务，应在实验前把所有候选统一改为该规则。
- 最优参数落在网格边界时，视开发证据决定是否扩展；注明搜索次数/时间，不能宣称找到全局最优。
- 同图展示每个模型 train 与 validation MAE，比较逐折与参数曲线。
  很低训练误差加较高验证误差提示方差问题；但未来时间段分布变化也会增加差距，不能直接等同于过拟合。
- 通过限制树深、增大叶样本、L2 和学习率控制复杂度，并看验证误差是否改善，而不是只看训练误差上升。
- 高 CO 尾部阈值只从每折训练目标计算，再诊断该折后续验证部分，避免验证信息定义阈值。
- 计划学习/成本曲线：使用各模型相同的按时间前缀样本量，25%/50%/100%，重复训练与测资源。
  时间覆盖随样本数改变，不能将其解读为纯粹样本数量的因果效应。
- 同折既调参又报告验证分数存在选择偏乐观；若需要更可靠开发比较可做嵌套时间 CV。
  本阶段没有做嵌套 CV，也没有任何候选模型或学习曲线的结果。

### 训练、预测时间与资源

- 单 CPU 数值线程、搜索单 worker；相同机器、环境和固定开发输入。每条结果携带 runtime/protocol ID。
- 搜索墙钟：包括全部配置、评分和最佳配置 refit；不能拿它当一次训练时间。
- 最终训练：完整开发集，先预热，再 3 次从未拟合的克隆训练，取中位数并保存原始秒数。
- 推断：包含填补、标准化等整个 Pipeline；固定同一条开发样本，预热后测 100 次，报中位数与 p95；
  固定 1,000 条开发样本批量，预热后测 10 次。批量均摊时间不能冒充真正单条调用延迟。
- 时间不含传感器采集、网络和生产服务开销；不能直接当端到端线上响应时间。
- 另一次训练测进程 RSS 相对基线增量（约 5ms 采样），并测 pickle 序列化体积。
  RSS=0 增量可能是采样/分配器复用，不等于模型不占内存；序列化体积不等于运行内存。
- 可扩展性实验尚未执行；之后各候选用相同训练规模、重复方案和环境。

### 测试集最终开启规则

公共框架没有测试预测调用。候选、约束和最终参数确定后，先把小组确认、数据哈希、协议、模型及参数写成
不可变的模型选择记录并取哈希，再拟合全部开发集，最后只给该 pipeline 生成一次测试预测。
同一预测向量计算所有预先声明的指标、分年诊断和约束检查，保存行号/运行环境/模型锁哈希。
写入结果后禁止第二次运行测试；失败则如实报告，不换模型、不重新调阈值。
这是后续待实现步骤，当前没有创建“已锁定”的假记录，也没有进行测试。
