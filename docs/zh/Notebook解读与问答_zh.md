# 公共 Notebook：用途、实测结果与问答准备

## 1. 先理解数据如何流动

```text
原始课程 CSV
  ├─ 全表：只检查列名、类型、缺失、有限值、重复与年份行数
  ├─ 2011–2013 开发数据
  │    ├─ 相同的五个时间折 → 每个模型调参 → train/validation 表
  │    ├─ 最佳开发参数 → 在全部开发数据拟合 → 只用开发输入测计算代价
  │    └─ 小组以后按约束选最终 pipeline
  └─ 2014–2015：仅保存分区行号，当前没有测试预测
```

每个折都重新创建、拟合自己的 Pipeline；先用这一折的训练数据学填补值与均值/标准差，
再处理未来的验证数据。不能把全数据预处理好后再交叉验证。

完整 Notebook 已在新内核运行成功。候选开关关闭时执行其单元格只会打印 NOT RUN，
**不表示候选模型本身已经运行**。在文件中有输出不等于该实验完成。

## 2. 按章节理解代码

| Notebook 章节 | 代码作用 | 你应能解释的要点 |
|---|---|---|
| 1 环境 | 固定线程和种子；导入包；记录 Python、版本、CPU、RAM、解释器、运行 ID | 可复现不只靠 random_state；时间比较依赖硬件和线程 |
| 2 数据 | 校验 CSV 哈希和字段，保存全表结构检查；按年封存，删除 raw 对象；开发数据概览 | 哈希证明使用同一文件，不能证明数据正确；读取做结构检查不同于用测试误差选模型 |
| 3 协议 | 指定目标、九个输入、阈值、gap；将时间折保存为一个共同列表 | 所有人用相同折，改变公共协议要统一重跑 |
| 3 评分函数 | `tolerance_coverage`、`negative_fraction`、`regression_metrics` | MAE、RMSE、R²、覆盖率各回答不同问题 |
| 3 模型与搜索 | `pipeline_for` 创建未拟合 Pipeline；`run_search` 统一调参、评分、保存明细 | Pipeline 内处理；GridSearchCV 自动克隆；refit 最佳参数后不拿它回算验证分数 |
| 4 OLS | 用单配置网格走同样评估流程，输出折分数与图；审核首折统计量 | 基准也必须用验证而非只看训练；OLS 没有 alpha 可调 |
| 5 成本 | `sample_seconds` 重复计时；`benchmark_pipeline` 测训练/单条/批量、RSS、体积 | 初次预热和重复的意义；批量吞吐不同于单条延迟；内存增量有局限 |
| 6 候选 | 三个模型及各自 8 个配置；三个独立负责人的单元格 | 关闭开关就不会训练；明确未运行；不凭猜测填写结果 |
| 7 比较 | 将已运行的性能与代价按模型名合并，检查草案约束，列实验状态 | 现在表里只有 OLS；不能评出全组最好模型 |
| 8 扩展验证 | 留训练/验证曲线、gap 稳健性、尾部误差、规模实验位置 | 这些还没做，不得写成报告发现 |
| 9 最终测试 | 仅给后续锁定/一次测试流程；检查当前未有测试对象或结果 | 当前没有可运行的最终测试调用；等小组确定再实现 |
| 10 贡献 | 提议的角色、实际工作待填、AI 用途 | 计划分工与真实贡献不同；任何人都可能被问整本 Notebook |

`GridSearchCV` 导出列里的 `split0_test_mae`、`mean_test_mae` 是 sklearn 对“该折验证部分”
的内部命名，不是 2014–2015 保留测试；公共表已改用 `validation` 避免混淆。

`run_search` 的 `best_estimator_` 在全部开发数据重拟合，用来以后部署或测成本；
其验证指标仍来自各个折内独立拟合的结果，没有用全开发拟合对象去伪造验证分数。

## 4. 适合准备的问答

**为什么选 CO？**
它是允许的实际排放预测目标，工程问题可定义为不依赖另一污染物测量的虚拟传感器。
开发数据存在长尾和接近零的值，适合讨论平均误差、大误差和容限覆盖的区别；最终目标仍须小组确认。

**为什么不预测 TEY？为什么输入里却有它？**
课程数据指南明确禁止 TEY 作目标，但允许作为过程输入。输入可用性仍需解释：
如果小时能量产出在需要预测 CO 时还没得到，就应删掉 TEY 并让全部模型重跑。

**为什么不随机 80/20？**
部署问题是用过去预测后续时期。随机切分会把邻近工况和未来时期混入训练，可能高估性能。
时间验证更贴近使用情境，不过不能保证时间独立。

**gap=24 是否最优？**
没有证据说它最优，这是待确认草案；相邻观测可能相关，留出一些行可减少紧邻信息共享。
CSV 无完整时间戳，所以 24 行不一定等于 24 小时。以后只在开发期做敏感性分析。

**为什么不直接用 MAPE 或“误差百分比 10%”？**
开发 CO 很多值接近零，百分比的分母会使指标不稳定。绝对误差用 mg/m³ 可解释。
但 ±1 mg/m³、90% 仍需应用方/小组认可，数据不能单独证明它就是合理容限。

**MAE 和覆盖率会选出同一个模型吗？**
不一定。MAE 衡量整体平均误差，覆盖率衡量误差落在容限内的比例。
因此本草案在家族内按 MAE 调参，之后按精度/速度约束筛选；这可能漏掉同家族中覆盖更好的配置。
小组若更重视覆盖率，应该在实验前统一更改家族内选择规则，不能测试后再换。

**为什么有缺失填补器但没有缺失？**
当前它不会填任何数据，保留它是为了明确未来输入缺失时的处理流程。
关键是填补中位数必须从每折训练部分计算，而非完整数据。

**为什么不删除湿度 >100% 和高 CO？**
轻微越界可能来自测量或舍入；高 CO 也可能是真实关键工况。
目前无记录错误证据，随意删除会扭曲任务。可做仅开发期的敏感性分析，但规则要统一记录。

**训练误差比验证误差低，是不是证明过拟合？**
泛化差距值得检查，但随时间工况变化也能造成差距。
需要结合复杂度曲线、正则化前后变化、时间折表现来区分，而不是只凭两列数字判断。

**为什么三个候选都用树模型？**
它们是三个不同的 sklearn 模型，可学习过程变量的非线性与交互；RF/Extra Trees 随机化不同，
HGB 是顺序提升。都有明确复杂度控制，适合共同比较。课程没有强制三种完全不同的大类。

**HGB 为什么关闭内部早停？**
它的默认内部验证可能随机分出数据，不符合本方案的时间顺序要求。
当前固定 max_iter 后用共同时间折选学习率、叶数与 L2；若以后采用早停，需专门设计时间验证。

**为什么记录搜索总时间和训练时间两种数？**
搜索包含很多次试验、验证评分与重拟合，反映建模成本；一次最终训练反映更新模型成本。
两者都重要，不能混成一个数。相同配置数也不保证相同运算量。

**为什么批量 1,000 条预测几乎和单条一样快？**
Python/Pandas 的调用与验证开销相对固定；向量化矩阵计算能摊薄开销。
吞吐能力和一次请求等待时间是不同指标，所以分别实测。

**测试集是否真的没见过？**
CW2 尚未评分，但 CW1 曾评估过相同年份，不能声称历史上完全没见过。
本次保持操作隔离，并披露这个限制；更强的新证据需要教师认可的新数据。

**如果最终测试未达约束怎么办？**
如实报告当前方案不满足，解释漂移/数据/目标的局限；不在同一个测试集继续调参或换模型。
若要新一轮开发，需要新的独立评估证据。

**怎样证明结果不是 AI 编的？**
Notebook 保存了实际执行输出，CSV/JSON 记录每折评分、参数、原始计时样本、数据哈希和环境。
同环境 Run All 可核查；模型未跑的部分写明 NOT RUN。AI 协助写入贡献记录，成员需审核并能解释代码。
